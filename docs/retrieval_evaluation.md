# Evaluation Protocol and Results — Longitudinal Patient-Context Retrieval and Responses

This is a **separate protocol**. The frozen Phase 5.5.2.1 OCR benchmark and the Phase 6 error-propagation benchmark are unchanged: all 133 files match `data/manifests/frozen_benchmarks_2026-11-01.sha256` (checked with `sha256sum -c`).

## 1. Data and splits
- Queries: `data/patient_retrieval/{train,validation,test}/queries.jsonl` (STAIR-Clinical generator, gold computed from the database).
- **Patient-separated** split by `sha256(patient_id)` (70/15/15): 473 / 89 / 109 patients; 0 patients shared between splits.
- Hyper-parameters (selector cut-offs, training settings) were chosen on **validation only**. Test was used only for the final runs reported below.
- Test runs use a stratified sample over the 14 query categories (fixed seed; the SHA-256 of the query-ID set is stored in each result file).

## 2. Methods compared (retrieval)
| ID | Method |
|---|---|
| R1 | BM25 over the patient's record texts (flat) |
| R2 | BGE-M3 dense over record concept texts (flat) |
| R3 | Hybrid RRF(BM25, dense) + query-understanding expansions |
| R4 | R3 + structured temporal operations — *B3 retrieval* |
| R5 | STAIR-Clinical, structural selector (no LLM) + structured ops |
| R6 | STAIR-Clinical, untrained base LM (Qwen2.5-0.5B-Instruct) with constrained scoring — out-of-the-box baseline |
| R7 | STAIR-Clinical, LoRA stage-1 selector (reduced-scale CPU run) |
| R8 | RRF(R5, R4) — *B4/B5 retrieval in the app* |
| R9 | RRF(R7, R4) |
| R10 | STAIR-Clinical, Mistral-7B-Instruct-v0.2 QLoRA stage-1 selector (reference configuration, 100 steps on a T4). Rankings are precomputed on GPU (`predict_stage1`) and loaded by `PrecomputedSelector`; stage 2 and evidence assembly run locally |
| R11 | RRF(R10, R4) |

All methods use the same patient-scoped candidate records. The harness asserts that no record from another patient is ever returned.

## 3. Metrics
- **Recall@k (capped)** = |gold ∩ top-k| / min(|gold|, k), for k = 1, 3, 5, 10. Gold = up to 3 most recent records per gold evidence path.
- **MRR**, **nDCG@10** (binary relevance).
- **Patient-context precision@10** = share of the top-10 that belongs to a gold evidence path. **Patient-context recall@10** = share of gold evidence paths covered in the top-10.
- STAIR methods only: **leaf exact match**, **leaf recall**, **leaf hit@1**, **group-path recall**, **invalid-path rate** (emitted paths not in the patient's hierarchy / all emitted paths).
- Uncertainty: **patient-clustered percentile bootstrap** (1,000 resamples) for 95% CIs; paired differences use a patient-clustered bootstrap with a two-sided bootstrap p. Raw numerators and denominators are stored in the JSON.

## 4. Response evaluation (B0–B5)
- B0 generic LLM; B1 reference RAG only; B2 STAIR patient retrieval only; B3 hybrid patient retrieval + reference RAG (no STAIR); B4 STAIR + hybrid + STAIR-routed references; B5 = B4 + emergency pre-emption, reconciliation, action policy, claim verification.
- Automated proxies: unsupported patient-claim rate (the verifier applied to every variant's raw output against the evidence that variant had), evidence support rate, historical-context coverage (gold concepts named in the answer), patient-history consistency (no number, date or entity mismatches), and action appropriateness on a fixed safety-probe set (emergency → EMERGENCY_OVERRIDE; prescribing decision → ABSTAIN_AND_NAVIGATE; vague new concern → ASK; unrecorded medication → ASK; ordinary history question → EXPLAIN).
- **Factual correctness is not automated.** A blinded review sheet (answers shuffled across variants, with the key stored separately) is produced for clinician raters. **No ratings have been collected.**

## 5. Results
All tables, CIs, numerators and denominators: **`docs/results_tables.md`** (auto-generated by `scripts/render_results.py` from the JSON result files). Main numbers:

### 5.1 Validation-only selector tuning
The structural selector's section cut-off was chosen on 151 validation queries (72 patients). With max 3 sections and no relative threshold, leaf exact match was 0.00 and STAIR-structural R@5 was 0.444. With max 2 sections and a relative threshold of 0.6, R@5 rose to 0.558 (leaf exact match 0.46). That setting became the default. Test data was not used for any choice.

### 5.2 Test split — non-LLM methods (599 queries, 108 unseen patients)
| Method | R@1 | R@5 | R@10 | MRR | Ctx-recall@10 |
|---|---|---|---|---|---|
| R1 BM25 | 0.462 | 0.546 | 0.618 | 0.535 | 0.606 |
| R2 BGE-M3 dense | 0.606 | 0.613 | 0.647 | 0.645 | 0.636 |
| R3 Hybrid RRF | 0.644 | 0.719 | 0.780 | 0.711 | 0.767 |
| R4 Hybrid + structured ops (B3) | **0.673** | **0.758** | 0.824 | **0.746** | 0.809 |
| R5 STAIR-Clinical (structural selector) | 0.489 | 0.567 | 0.622 | 0.567 | 0.648 |
| R8 STAIR + hybrid (B4/B5) | 0.636 | 0.720 | **0.873** | 0.719 | **0.870** |

- **STAIR does not improve top-5 retrieval over the strong hybrid baseline.** STAIR alone is significantly worse than R4 (ΔR@5 = −0.191, 95% CI [−0.239, −0.139]). STAIR+hybrid is not significantly different from R4 on R@5 (Δ −0.038, CI [−0.079, 0.005], p = 0.08) or MRR. **It does retrieve more of the needed evidence within the top 10**: R@10 0.873 vs 0.824, context recall@10 0.870 vs 0.809 (CIs in results_tables.md), at lower context precision (0.308 vs 0.411).
- **Where structure helps:** questions answered by a section rather than by keywords. Last visit: R@5 1.00 vs 0.06. Relevant history for a new symptom: 0.82 vs 0.57. Allergy check: 0.79 vs 0.32 (n = 6). Organ-system labs: 0.93 vs 0.88.
- **Where it hurts:** lexically specific requests whose concept name is in the query (medication changes 0.16 vs 1.00, procedures 0.28 vs 1.00, lab trends 0.35 vs 0.83). Here stage-1 routing to the wrong section, or the stage-2 group cut, drops evidence that keyword matching finds trivially.
- **Invalid paths: 0 / 3,334** emitted paths (all paths validated against the patient's hierarchy before resolution).
- Hybrid fusion is clearly better than BM25 alone (ΔR@5 +0.172, CI [0.144, 0.200]). Structured temporal operations add +0.04 R@5 over plain hybrid, mostly on *diagnoses in year X* and *medications during an episode*.

### 5.3 SearchTome (official reduced release; flat baselines, test)
BM25 is the strongest flat baseline on every domain except social sciences (medicine R@1 0.678, n = 1,996; law 0.767). BGE-M3 dense is consistently weaker on this textbook-section task. No fine-tuned STAIR result on SearchTome is reported, because no GPU was available.

### 5.4 Responses B0–B5 (8 test-split clinical queries + 5 safety probes; llama3.2:3b; structural STAIR selector)
| Variant | Unsupported patient-specific claims (raw LLM output) | Historical-context coverage | Action appropriateness (probes) | Latency (s) |
|---|---|---|---|---|
| B0 generic LLM | 1.00 | 0.38 | 1/5 | 15 |
| B1 reference RAG | 1.00 | 0.38 | 1/5 | 30 |
| B2 history only (STAIR) | 0.65 | 0.66 | 1/5 | 47 |
| B3 hybrid history + RAG | 0.54 | 0.79 | 1/5 | 82 |
| B4 STAIR + hybrid + RAG | 0.55 | 0.79 | 1/5 | 63 |
| B5 full MedResolve | 0.52 raw → **0 released** | 0.79 | **5/5** | 42 |

- Without patient history (B0, B1), every patient-specific statement is unsupported by construction. Adding history raises the supported share and the coverage of gold concepts (0.38 → 0.79).
- Even with history, about half of the 3B model's raw patient statements cannot be verified (missing citations, extra details). **The B5 verification gate released 0 unsupported patient-specific claims** across all responses.
- B5's selective policy chose the expected action on all five probes (emergency pre-emption in 6 ms, with no retrieval or LLM; abstention on a stop-medication question; ASK for a vague concern and for an unrecorded medication; EXPLAIN for an ordinary history question). The baselines have no policy and always explain.
- **Caveats:** n = 8 clinical queries (wide CIs in results_tables.md). The coverage proxy is lexical, so it can credit a generic answer that happens to name the gold concept (B0 scores 0.38 this way). Factual correctness is **unrated**; the blinded sheet is at `evaluation/experiments/response_evaluation/results/blinded_review_sheet_*.csv`. B3 and B4 do not differ meaningfully here.

- **Fine-tuning works for the routing skill:** R7 vs R6 ΔR@5 = +0.304 (95% CI [0.271, 0.339]); ΔMRR = +0.265. Validation section R@1 rose from 0.227 to 0.780 (training_methodology.md).
- **But the reduced-scale LoRA router is not better end to end.** It is below the structural selector (ΔR@5 −0.076, CI [−0.116, −0.038]) and well below hybrid retrieval. Category analysis shows near-perfect routing for *last visit* (1.00) and good routing for *latest measurement* (0.85), but failures on *procedure history* (0.00), *immunization history* (0.06) and *lab trend* (0.22). - **Fused with hybrid retrieval (R9)**, the trained router gives the best top-1 precision (R@1 0.716 vs 0.673; MRR 0.770 vs 0.746, Δ +0.024, CI [−0.016, 0.065], not significant). R@5 is slightly lower and also not significant (Δ −0.036, CI [−0.077, 0.006]).
- **Hallucinated paths:** 0 invalid paths for every STAIR variant. Constrained scoring makes invalid paths impossible, and the database validation layer rejects anything else. For contrast, unconstrained zero-shot llama3.2:3b produced non-existent section titles 20/30 times on SearchTome (§5.6).

### 5.6 SearchTome — out-of-the-box LLM baselines (medicine, official reduced release)
- Untrained Qwen2.5-0.5B with the original STAIR prompt + constrained scoring: R@1 0.05 (3/60), R@3 0.10; about 49 s/query on CPU (121-leaf ToC). Like the paper's Mistral out-of-the-box baseline (0.138), a model without fine-tuning is far below BM25 (0.678 on the full test set).
- Zero-shot llama3.2:3b, free generation: **invalid (non-existent) leaf rate 0.667 (20/30)**, exact match 0.10 (3/30).

Paired, patient-clustered bootstrap (599 queries, 108 patients):
- **R11 − R4:** ΔR@5 **+0.109** (95% CI [0.075, 0.142]), ΔMRR **+0.127** ([0.099, 0.154]), both p < 0.001. This is the first STAIR variant that significantly beats hybrid retrieval.
- **R10 − R4** (router alone): ΔR@5 +0.024 ([−0.012, 0.061]), ΔMRR +0.032 ([−0.007, 0.067]). Not significant. The router on its own matches hybrid retrieval; the gain comes from fusing the two.

- **R10 − R7** (7B vs 0.5B router): ΔR@5 +0.292 ([0.262, 0.319]), ΔMRR +0.345. **R11 − R9:** ΔR@5 +0.145 ([0.120, 0.173]).

Validation and test patients are disjoint from training, but query templates are shared. The result shows the router learns the hierarchy well. It does not show generalization to real patient language, and none of this is clinical evidence.

## 6. Answer to RQ1 (does STAIR improve retrieval?)
**Yes, with a reference-scale router fused with hybrid retrieval. No, at the reduced CPU scale.** On 108 unseen synthetic patients:
- With the reduced-scale Qwen-0.5B router (R7/R9) or the structural selector (R5/R8), no STAIR variant significantly beats hybrid + structured retrieval (R4) on R@5 or MRR (§5.2, §5.5).
- With the Mistral-7B QLoRA router (reference configuration, 100 steps), fusion with hybrid retrieval (R11) significantly beats R4: R@5 0.867 vs 0.758 (Δ +0.109, CI [0.075, 0.142]) and MRR 0.873 vs 0.746. The router alone (R10) is on par with R4, not significantly better (§5.7).

So hierarchical routing adds information that lexical/dense retrieval misses ("where" a fact lives: last visit, allergies, current medications, relevant history). It pays off only once the router is accurate (section hit@1 0.958 trained vs 0.79 untrained Mistral vs 0.71 structural), and only in combination with hybrid retrieval. The untrained 7B router fused with hybrid ties R4, so the improvement is attributable to STAIR-Clinical fine-tuning (ΔR@5 +0.145 trained vs untrained, CI [0.120, 0.171]). Caveats: one run, synthetic template-generated queries, GPU-only router. This is not clinical evidence.

## 7. Configuration used by the app
`STAIR_BACKEND=auto` loads the installed LoRA adapter (R9-style fusion, B4/B5). Set `STAIR_BACKEND=structural` for the non-LLM selector (R8, about 5 s faster per query on CPU). The B0–B5 response evaluation in §5.4 used the structural selector, because it ran before the adapter existed.
